# অফলাইন ফরম ফিলাপ — পরিকল্পনা (২০২৬-১০-১৯, মালিকের সাথে আলোচনায় ঠিক হলো)

> "অফলাইন" মানে **কাগজের ফরম** (ওয়েবসাইটের ফরম নয়)। নকশা আর তথ্য তুলতে Gemini, অর্থাৎ ইন্টারনেট, লাগবে।
> বাইরের ব্লুপ্রিন্ট (`Downloads\code_artifact.md`, Python/session) বাতিল করা হলো, কারণ আমাদের কাঠামোর সাথে মেলে না। শুধু মূল ভাবনাটি নেওয়া হলো।

## ১. নীতি
- এটি **আলাদা সেবা**: নিজের পাতা, নিজের মডিউল। কম্পোজ, হুবহু বা স্টুডিওর UI ও প্রবাহে কোনো বদল নয়।
- পুরোনো ইঞ্জিন শুধু **ডাকা হবে, বদলানো হবে না**। নতুন কিছু লাগলে মোড়ক বানানো হবে `js/form-fill/`-এ।
- কোড লিখবে Gemini-ট্যাব (বান্ডেল)। Claude যাচাই করবে, বসাবে, টেস্ট চালাবে আর push করবে।

## ২. ব্যবহারকারীর প্রবাহ
1. **ফরম তৈরি:** খালি ফরমের ছবি বা PDF → চালু হুবহু-ক্যাপচার (**চালু OCR-প্রম্পট, কোনো বদল নয়**) → নকশা (IR) → "আমার ফরম" তালিকায় সেভ (IndexedDB)। এরপর একই ফরম বারবার ব্যবহার করা যাবে।
2. **পূরণ:** "আমার ফরম" থেকে ফরম বাছাই → NID, সার্টিফিকেট, ছবি আর স্বাক্ষর দেওয়া → **ফরমের ঘর থেকে বানানো আলাদা প্রম্পট** (নিচে) → JSON মান → ঘরে বসানো।
3. **ফল:** প্রিভিউ আর "পূরণ হয়নি"-তালিকা (হাতে লেখার সুযোগ) → .docx, বিজয় বা .doc (`FayzarExport.produce`)।
4. গ্রাহকের তথ্য **কোথাও সেভ হবে না**। কাজ শেষ হলে মেমোরি থেকে মুছে যাবে।

## ৩. ধাপ ২-এর প্রম্পট (নতুন মডিউলে; ai-ocr-engine-এর প্রম্পট অক্ষত)
- পাঠানো হবে ঘরের তালিকা (`id: "লেবেল"`) আর ডকুমেন্টের ছবি। নকশা পাঠানো হবে না।
- নিয়ম:
  - বানান ডকুমেন্টে যেমন, হুবহু তেমন।
  - বাংলা লেবেলে বাংলা অঙ্ক, ইংরেজি লেবেলে ইংরেজি অঙ্ক।
  - না পেলে `null`, অনুমান করবে না।
- ফেরত আসবে শুধু JSON `{slotId: value|null}`। কল যাবে চালু `executeGeminiRequest` দিয়ে।

## ৪. মডিউল (প্রস্তাব)
| অংশ | ফাইল |
|---|---|
| পাতা + অ্যাপ | `form-fill.html`, `js/form-fill-app.js` |
| ঘর চেনা (ডট বা ড্যাশের সারি, `label_value`, ছবির ঘর) | `js/form-fill/slots.js` (`FayzarSampleTemplate.fromIR` ডেকে) |
| প্রম্পট আর পার্স | `js/form-fill/extract.js` |
| বসানো (ডটের জায়গায় মান; ছবির ঘরে ছবি) | `js/form-fill/inject.js` (`FayzarSampleTemplate.fill` ডেকে) |
| "আমার ফরম" স্টোর | `js/form-fill/store.js` |
| ছবি বা স্বাক্ষর ক্রপ | `tools.html`-এর রিসাইজারের যুক্তি পুনর্ব্যবহার |
| যোগসূত্র | `services.html`-এ কার্ড আর ফুটার-লিংক |

## ৫. ধাপ (প্রতিটির শেষে টেস্ট আর রিপোর্ট)
- ☐ **FF0** কোডে যাচাই: হুবহু-IR-এ খালি "ছবি" বক্স কী রূপে আসে, আর builder-এ ছবি বসানো যায় কি না।
- ☐ **FF1** পাতা, কার্ড আর "আমার ফরম" স্টোর (বান্ডেল ক)।
- ☐ **FF2** ঘর চেনা আর বসানো, Node-টেস্টসহ, Gemini ছাড়া (বান্ডেল খ)।
- ☐ **FF3** ধাপ-২ প্রম্পট আর ছবির ঘর (বান্ডেল গ)। তারপর আসল NID-নমুনা দিয়ে E2E।
- ☐ **FF4** গোপনীয়তা-সতর্কবার্তা, "পূরণ হয়নি" হাতে-লেখা, বিজয় বা .doc যাচাই।

## ৬. খোলা প্রশ্ন
- ছবির ঘরে ছবি বসবে নাকি ফাঁকা থাকবে (প্রিন্টের পর আঠা দিয়ে লাগানো হয়)? দুটিই অপশন রাখা যায়।
- পরীক্ষার জন্য নমুনা: খালি ফরম ২–৩টি + নমুনা NID বা সার্টিফিকেট (আসল তথ্য ঝাপসা করে)।
